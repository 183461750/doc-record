# 依赖漏洞清理（dependabot 15 项）

的 15 项完全对齐，**以这两个为准**。注意 `GET /repos/{owner}/{repo}/dependabot/alerts`

## 3. overrides 的取舍原则

1. **先升母包**：这一批里多数是 astro / starlight / mermaid 的深层传递依赖，dependabot 的
   all-minor-patch 组（astro 7.3.8、starlight 0.42.6、mermaid 12.1.0、markdown-remark 7.3.2）
   一次性带走了 devalue、http-cache-semantics、katex 三项；
2. **母包升完仍有残留，才用 `pnpm.overrides` 精确兜底**（本仓库已有该模式：`lodash-es`）；
3. **强制版本前必须核对父包声明的范围**（不能凭"补丁版本号更大"就强制）：
   `postcss-selector-parser` 的父包 `postcss-nested@6.2.0` 只允许 `^6.1.1`，而 6.x 线最高就是
   受影响的 6.1.4，修复只存在于 7.x —— 这属于**越界强制**，必须额外验证（§4）。
   其余三项的强制都在父包范围内（`^3.4.12` / `^1.2.1` / `^1.6.0`）✓。

## 4. 越界强制的验证方法：CSS 产物逐字节对比

`postcss-selector-parser` 参与 expressive-code 的代码块样式管线，跨大版本有回归风险，
而 e2e 不覆盖代码块样式的细节。做法：

1. 改动前构建一次，记录 `dist/**/*.css` 每个文件的（尺寸, sha256）；
2. 强制升级后重建，逐文件比对：**本次 6 个 CSS 文件全部逐字节一致** → 保留该 override。

> 踩坑记录：最初用"把所有 CSS 正文拼接后取一个指纹"的方式比较，得到过假阳性（指纹不同），
> 原因是脚本按尺寸排序、同尺寸文件顺序不稳定。结论以**逐文件比对**为准。

## 5. 已知不可修：`braces` 3.0.3（high，GHSA-vfj7-8cjw-p6xm）

- 现象：`braces` 全线（`<=3.0.3`）无补丁，也没有 4.x 可升；
- 路径：`.>starlight-llms-txt>micromatch>braces` —— 该路径只在**构建期**生成 llms.txt 时
  做 glob 匹配，输入是本仓库自己的配置常量，**不存在攻击者可控输入**；产物是静态文件，
  运行期不加载该包；
- 判定：**可接受**，不为它引入 fork 或 patch 机制；上游发布修复后再跟进。
  同类判断标准沿用：构建期 + 自有输入 + 不进产物 ⇒ 可接受；反之必须修。

## 6. 附带的非安全升级

- npm：`starlight-blog` 0.29.0 → 0.30.2、`starlight-llms-txt` 0.11.0 → 0.12.0、
  `@playwright/test` → 1.64.1；
- **Playwright 需重新下载浏览器**（chromium v1248，185.8 MiB）：CI 由 `playwright install` 负责，
  本机首次跑 e2e 前需执行 `pnpm exec playwright install chromium`，否则全部用例会以 1ms 失败
  （症状是浏览器可执行文件缺失，不是断言失败）；
- GitHub Actions：`actions/checkout` v6 → v7（新增"禁止为 `pull_request_target`/`workflow_run`
  检出 fork PR"的安全加固，用法与输入不变）、`actions/upload-artifact` v4 → v7
  （新增可选 `archive` 参数，本仓库用法不变）。
